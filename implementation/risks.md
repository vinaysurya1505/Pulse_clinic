# Risk Register and Mitigation Strategy

This document provides a comprehensive risk register for the Pharmacy AI Agent application in accordance with Pack 1.2 specifications, Prompt 1A corrections, and the authoritative 30-prompt milestone map.

---

## Comprehensive Risk Register

| Risk ID | Risk Title | Category | Likelihood | Impact | Prevention Action | Detection Action | Recovery Action | Designated Owner | Release Gate |
| ------- | ---------- | -------- | ---------- | ------ | ----------------- | ---------------- | --------------- | ---------------- | ------------ |
| **RSK-001** | Negative stock resulting from inventory deduction race conditions | Inventory | Medium | High | Firestore transactions enforcing strict stock checks (`currentStockUnits >= requestedUnits`) before deduction. | Automated integration tests checking non-negative invariants; audit logging on low stock. | Issue inventory adjustment ledger entry after physical audit; log variance report. | Backend Lead | Prompt 7 |
| **RSK-002** | Concurrent sales on final batch units | Concurrency | Medium | High | Optimistic locking on batch documents (`batch.stockUnits`) within atomic Firestore transaction. | Firestore transaction retry limits and explicit `ABORTED` error handling in API response. | Prompt cashier to refresh cart with latest batch availability; line item updated. | Lead Architect | Prompt 7, 13 |
| **RSK-003** | Duplicate invoice allocation during peak traffic | Financial | Low | Critical | Server-side transaction on store counter document `stores/{storeId}/counters/invoices` for sequential string formatted numbers (`INV-YYYYMM-XXXXXX`). | Daily automated index integrity check for unique invoice numbers per store. | Manual database investigation via audit log; void duplicate candidate with counter correction. | Lead Architect | Prompt 13 |
| **RSK-004** | Duplicate CSV file import leading to duplicate inventory or employees | Operations | Medium | Medium | Compute SHA-256 file hash before upload; check against `importJobs` collection for past successful imports. | Pre-ingestion validation check matching hash and filename against historical jobs. | Mark job as `REJECTED_DUPLICATE`; prompt user with past import job link. | Fullstack Engineer | Prompt 8 |
| **RSK-005** | Partial CSV failure during bulk ingestion | Operations | Medium | High | Dynamic write-budget chunking; write max 25 rows per batch transaction with atomic rollback per batch chunk. | Record chunk failure in `importJobs/{jobId}/errors`; set job status to `COMPLETED_WITH_ERRORS`. | Provide itemized error CSV download; allow re-upload of corrected error rows only. | Backend Lead | Prompt 8 |
| **RSK-006** | Incorrect pack conversion resulting in wrong unit prices or stock counts | Inventory / Math | Medium | High | Enforce mandatory base unit definition (`tablets`, `capsules`, `ml`); validate `stripSize > 0` at schema level. | Unit tests for `packToUnits` and `unitsToPacks`; UI preview showing computed base unit price before saving. | Create stock adjustment ledger record correcting base units; update medicine master. | Backend Lead | Prompt 6 |
| **RSK-007** | Floating-point rounding errors in monetary calculations | Financial | High | Critical | Eliminate all floating-point math; enforce integer paise representation (`*Paise`) derived via `parseDecimalToPaise`. | CI lint rule blocking `Math.round(x * 100)` or `parseFloat` on currency values; double-entry ledger checks. | Recalculate invoice totals using versioned paise calculation engine; issue ledger correction. | Lead Architect | Prompt 11 |
| **RSK-008** | GST tax calculation misconfiguration (CGST/SGST/IGST split) | Legal / Financial | Medium | High | Server-side state-code comparator (`store.stateCode` vs `customer.stateCode`); hardcoded GST slab validation (0, 5, 12, 18, 28%). | Unit tests verifying IGST for inter-state vs CGST+SGST for intra-state; daily ledger audit. | Issue GST adjustment credit note; file corrected GST return with tax advisor. | Security Lead | Prompt 11, 29 |
| **RSK-009** | Doctor commission regulatory non-compliance | Legal | High | Critical | Configurable feature toggle `enableDoctorCommission: false` by default; explicit legal compliance record required before activation. | Automated startup check verifying toggle state; audit logging of configuration mutations. | Disable feature immediately if activated without signed legal approval record. | Product Owner | Prompt 10, 11, 29 |
| **RSK-010** | Unauthorized cross-tenant store access | Security | Low | Critical | Firebase Auth token custom claim verification and Firestore Security Rules enforcing `request.auth.token.storeId == resource.data.storeId`. | Automated tenant isolation security rules emulator test suite (100% path coverage). | Revoke user Firebase Auth token; force logout across active sessions; rotate credentials. | Security Lead | Prompt 4, 5 |
| **RSK-011** | Role escalation via client-side request tampering | Security | Low | Critical | Server-authoritative role verification reading `stores/{storeId}/members/{uid}` inside Express auth middleware. | CI integration tests attempting privileged API calls with low-privilege tokens (`Pharmacist`, `Accountant`). | Revoke assigned member role; reset to `Pharmacist`; notify Store Owner via security alert. | Security Lead | Prompt 5, 25 |
| **RSK-012** | Approval code brute-force attacks | Security | Medium | High | Max 3 incorrect entry attempts per approval code within 15 minutes; rate limiting on code verification endpoint. | Monitor failed OTP verification attempts in rate limiter memory; trigger alert on 3 failures. | Invalidate approval code immediately (`EXPIRED_MAX_ATTEMPTS`); require new request to Super Admin. | Security Lead | Prompt 17, 18 |
| **RSK-013** | Exposure of approval code in API logs or client responses | Security | Low | Critical | Approval code never stored in plain text (only HMAC-SHA256 hash in DB); never returned in API responses to cashier. | Log scrubber pipeline masking code patterns; API response schema validation omitting code fields. | Rotate `HMAC_SECRET` key; invalidate all active approval requests immediately. | Security Lead | Prompt 17, 18 |
| **RSK-014** | Exposure of outbox AES-256 encryption key | Security | Low | Critical | `OUTBOX_ENCRYPTION_KEY` injected solely via environment variables; never logged or serialized to Firestore. | Static analysis scanning code for hardcoded secrets; environment variable pattern checker on boot. | Rotate `OUTBOX_ENCRYPTION_KEY`; re-encrypt active outbox pending queue items using rotation script. | Security Lead | Prompt 17, 25 |
| **RSK-015** | Email delivery failure for approval codes or notification outbox | Operations | Medium | Medium | Resend interface wrapped with exponential backoff retry handler (max 3 retries); retry counter in outbox. | Worker heartbeat logging failed delivery attempts (`FAILED_RETRY_LIMIT`); health check endpoint alert. | Provide resend approval code trigger (`POST /api/v1/bills/:id/resend-approval`). | Backend Lead | Prompt 17, 22 |
| **RSK-016** | Duplicate refund processed for a single invoice | Financial | Low | Critical | Unique Firestore index/document path for refund by invoice ID (`stores/{storeId}/refunds/{invoiceId}`); transaction lock. | Invariant check asserting `invoice.status == 'FINALIZED'` prior to processing refund. | Reject duplicate refund transaction; display existing refund audit trail to operator. | Backend Lead | Prompt 18 |
| **RSK-017** | Incorrect split-payment refund allocation across payment modes | Financial | Low | High | Server-side validation enforcing `sum(refundModes.amountPaise) == totalRefundPaise` and `modeRefund <= originalModePaid`. | Pre-refund validation unit tests checking split-payment refund boundaries. | Issue payment ledger adjustment reversing excess allocation; notify cashier. | Backend Lead | Prompt 18 |
| **RSK-018** | Employee PII exposure via API responses or client-side storage | Privacy | Low | High | Default MVP stores strictly approved masked values (`aadhaarLastFour`, `panLastFour`). Raw PII prohibited without consent. | Integration tests verifying `Accountant` and `Pharmacist` cannot fetch unmasked PII. | Revoke compromised tokens; log privacy incident report; notify affected employee per store protocol. | Security Lead | Prompt 10, 25, 29 |
| **RSK-019** | Unbounded Firestore query costs from missing limits or full scans | Infrastructure | Medium | High | Enforce mandatory limit (`max 50` rows) and cursor-based pagination on all list queries; no offset pagination. | Firestore rule & index validator checking query constraints; billing budget alerts in Firebase console. | Refactor offending API query to use structured composite index and cursor boundaries. | Backend Lead | Prompt 24 |
| **RSK-020** | Hot document contention on daily aggregate ledgers | Performance | Medium | High | Atomic update operations on `dailySummaries` document; asynchronous background rollups if throughput spikes. | Monitor Firestore latency and `ABORTED` transaction error rate metrics. | Implement sharded counter aggregation if transaction retry rate exceeds threshold. | Lead Architect | Prompt 20, 24 |
| **RSK-021** | Missing Firestore composite indexes causing production query failures | Infrastructure | Low | High | Comprehensive `firestore.indexes.json` checked into Git; tested against Emulator during integration test run. | CI step executing all system queries against local Firestore Emulator with missing index reporting. | Deploy updated `firestore.indexes.json` via Firebase CLI prior to API deployment. | Backend Lead | Prompt 24 |
| **RSK-022** | Discrepancy between daily report summary documents and itemized ledgers | Financial | Low | High | Nightly automated ledger reconciliation job computing `sum(ledgers) == dailySummary.netSalesPaise`. | Automated reconciliation worker running daily; generates audit alert on delta > 0. | Trigger ledger re-aggregation pipeline for affected date; flag variance in financial report. | Backend Lead | Prompt 20, 22 |
| **RSK-023** | Scheduled Firestore database backup job failure | Operational | Low | Critical | Automated GCP Scheduled Cloud Function taking daily Firestore export to Cloud Storage bucket. | Cloud Monitoring alert on backup export failure or missing daily backup object. | Trigger manual GCP CLI backup export immediately; inspect IAM permissions and storage quota. | DevOps Lead | Prompt 29 |
| **RSK-024** | Restore procedure failure during emergency disaster recovery | Operational | Low | Critical | Automated dry-run restore procedure verified into isolated staging project during Prompt 29 pre-flight. | Post-restore schema validation and record count check script. | Execute point-in-time recovery runbook using secondary snapshot; engage Google Cloud support. | DevOps Lead | Prompt 29 |
| **RSK-025** | Vercel deployment misconfiguration linking staging frontend to production backend | Infrastructure | Low | Critical | Environment-locked build scripts enforcing `NEXT_PUBLIC_API_URL` validation during Vercel build step. | Automated health check asserting `api.environment == frontend.environment` on app launch. | Terminate frontend deployment; update Vercel environment variables; re-trigger pipeline. | DevOps Lead | Prompt 28 |
| **RSK-026** | Staging environment accidentally accessing production Cloud Firestore database | Security | Low | Critical | Isolated GCP projects and service account credentials (`pharmacy-staging` vs `pharmacy-prod`). | Application boot check verifying GCP project ID matches expected `NODE_ENV`. | Immediately revoke compromised staging service account key; trigger production security audit. | Security Lead | Prompt 28 |
| **RSK-027** | Leakage of backend secrets (`HMAC_SECRET`, `OUTBOX_ENCRYPTION_KEY`) into frontend bundle | Security | Low | Critical | Frontend bundle audit CI step verifying no `process.env` non-`NEXT_PUBLIC_` variables are included in static output. | `next build` wrapper script checking build output for secret string patterns. | Revoke and rotate leaked keys immediately; redeploy backend with new credentials. | Security Lead | Prompt 25, 28 |
| **RSK-028** | Sale of expired medicines due to manual override or missing FEFO sorting | Clinical / Legal | Medium | Critical | Server-side validation blocking billing of batches where `expiryDate <= invoiceDate`; automatic FEFO batch selection. | Unit tests asserting expired batches are rejected during cart item validation. | Issue batch recall alert; notify customer if dispensed; log incident in drug compliance register. | Product Owner | Prompt 7, 12 |
| **RSK-029** | Production database contamination with test data | Operations | Low | High | Strict prohibition of test scripts in production; emulator-only test runner configurations. | Guard check in test framework aborting execution if `FIREBASE_PROJECT_ID == 'pharmacy-prod'`. | Purge identified test tenant/store using backend cleanup script; verify isolation logs. | DevOps Lead | Prompt 27, 28 |
